## 1. Зачем типы

Представь: у каждого слота есть **бирка** — «сюда можно класть только такое».

Компилятор смотрит на бирку **до запуска**. Если не подходит — ошибка ещё до `main()`.

В JS бирок почти нет:

```js
let x = 10;
x = 'Alex'; // ок
```

В Dart бирка есть всегда. Даже у `var` — её вывели из первого значения и закрепили.

Зачем:
- ловить глупые ошибки раньше;
- читать код проще;
- tooling (автодополнение) понимает, какие методы доступны.

## 2. Числа: `int`, `double`, `num`

| Тип | Что можно положить | Пример |
|---|---|---|
| `int` | целое | `10`, `-3` |
| `double` | дробное | `10.5`, `3.0` |
| `num` | и целое, и дробное | сначала `10`, потом `10.5` |

`num` — общий предок «число вообще».

```dart
num x = 10;   // ок: int подходит под num
x = 10.5;     // ок: double тоже num
```

### Деление — частая ловушка

```dart
5 / 2   // значение 2.5, тип double — обычное / всегда double
5 ~/ 2  // значение 2,   тип int    — целочисленное деление
```

В JS `5 / 2` тоже `2.5`, но отдельного `~/` нет. В Dart для «делить нацело» используй `~/`.

## 3. Другие базовые типы

- `String` — текст: `'Alex'`
- `bool` — `true` / `false`

В Dart **нет** `undefined`. Пустота — только `null`.

---

## 4. `null` и знак `?`

Знак `?` у типа = «этот тип **или** `null`».

```dart
String name = 'Alex'; // только строка; null нельзя
String? nick;         // строка или null
```

Правило:
- без `?` — `null` запрещён;
- с `?` — `null` разрешён.

Это называется **null safety**: компилятор помогает не получить неожиданный `null` там, где ты его не ждал.

---

## 5. Иерархия: почти всё — объект

Учебно:
- вершина ненулевой иерархии — `Object`;
- с возможным `null` — `Object?`.

На любой тип спрашивай два вопроса:

1. **Что можно положить в слот?**
2. **Что компилятор разрешает вызывать?**

| Тип | Что можно положить | Что компилятор разрешает вызывать |
|---|---|---|
| `String` | только строка, не `null` | методы строки: `.length`, … |
| `String?` | строка или `null` | осторожно: сначала проверить на null |
| `Object` | любой объект, не `null` | только общее (`toString`, `==`…) — **не** `.length` |
| `Object?` | любой объект или `null` | ещё меньше гарантий, пока не сузишь тип |
| `dynamic` | почти что угодно | компилятор **почти не проверяет** вызовы |

### `Object` vs `dynamic` — главный камень

```dart
Object a = 'hello';
// a.length; // ошибка компиляции: бирка Object, length у неё нет

dynamic b = 'hello';
print(b.length); // компилятор пропускает
```

`Object` = «храню что угодно ненулевое, но **не знаю что именно**».  
`dynamic` = «почти не проверяй меня на этапе компиляции».

```dart
dynamic b = 'hello';
b = 10;
// print(b.length); // компилятор молчит, падение в runtime
```

И отдельно:

```dart
dynamic x = 10;
x = 'Alex'; // это НЕ ошибка ни на компиляции, ни в runtime
```

Смена значения у `dynamic` разрешена. Падает только вызов несуществующего члена (например `.length` у числа).

---

## 6. `var` ≠ `dynamic`

```dart
var x = 10;      // выведен int
x = 20;          // ок
// x = 'Alex';   // ошибка компиляции

dynamic y = 10;
y = 'Alex';       // ок
```

| | `var x = 10` | `dynamic x = 10` |
|---|---|---|
| бирка | зафиксирован `int` | проверки почти сняты |
| `x = 20` | ок | ок |
| `x = 'Alex'` | ошибка компиляции | ок |
| `.length` после числа | не дойдёт / не то | может упасть в runtime |

Сравнение с JS: `let x = 10; x = 'Alex'` ближе к `dynamic`, не к `var`.

---

## 7. Типичные ошибки

1. Думать, что `var` как JS-переменная без типа.
2. Путать `Object` и `dynamic`.
3. Считать `dynamic x = 10; x = 'Alex'` runtime-ошибкой.
4. Забыть, что `/` всегда даёт `double`.
5. Переворачивать формулировку: «dynamic почти не пропускает» — неверно. Верно: почти **не проверяет** / почти **пропускает** вызовы.
