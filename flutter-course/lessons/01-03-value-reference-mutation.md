# 1.3 — Value, Reference, Mutation, Shallow Copy

Статус: тема закрыта на 100%. Это конспект для повторения.

Это один из самых важных фундаментов для Dart/Flutter: state, списки, виджеты, баги «почему изменилось не то».

---

## 1. Две разные операции

Всегда разделяй:

1. **Переприсвоить имя** — положить в слот другое значение/другую ссылку: `a = ...`
2. **Мутировать объект** — изменить уже существующий объект по ссылке: `a.score = 10`, `list.add(1)`

Если путать эти две операции, будут ломаться `final`, state management и отладка.

---

## 2. Простые значения (учебная модель)

Для простых вещей вроде числа в учебной модели:

```js
let a = 10;
let b = a;
b = 20;
// a всё ещё 10
```

При `let b = a` копируется **значение**. `a` и `b` дальше независимы.

В Dart похожий смысл для переприсваивания:

```dart
var a = 10;
var b = a;
b = 20; // a остаётся 10
```

Уточнение (уже зафиксировано в прогрессе): в Dart `int` технически объект, но **неизменяемый**. Мутировать «внутри 10» нельзя. Поэтому для практики: число в слоте ведёт себя как значение; «поменять число» = положить в слот другое число.

---

## 3. Объекты и ссылки

Когда в слоте объект (list, map, свой class), присваивание копирует **ссылку**, не весь объект.

```dart
final a = [1, 2, 3];
final b = a; // скопировали ссылку
```

Картина:

```text
слот a ──┐
         ├──► один и тот же List в heap: [1, 2, 3]
слот b ──┘
```

Ключевая формулировка:

> `a` и `b` могут хранить ссылки на один объект; сами ссылки не меняются, а через одну из них можно мутировать общий объект.

---

## 4. Mutation

**Mutation** = изменение уже существующего объекта.

```dart
final a = [1, 2, 3];
final b = a;
b.add(4);
// a тоже «стал» [1, 2, 3, 4], потому что это тот же список
```

Здесь:
- слоты `a` и `b` по-прежнему хранят ту же ссылку;
- изменился **объект** в heap.

Это не переприсваивание. Переприсваивание выглядело бы так:

```dart
// b = [10, 20]; // другая ссылка в слоте b (если бы b не был final / если var)
```

---

## 5. Несколько ссылок на один объект

Нормальная ситуация:

```dart
var user = {'name': 'Alex'};
var ref1 = user;
var ref2 = user;
ref1['name'] = 'Sam';
// ref2['name'] тоже 'Sam'
```

Один объект — три способа до него добраться (`user`, `ref1`, `ref2`).

---

## 6. Shallow copy (поверхностная копия)

Иногда нужен **новый** внешний объект, чтобы не делить тот же контейнер.

В JS часто:

```js
const a = { nested: { n: 1 } };
const b = { ...a }; // shallow copy
```

- внешний объект новый;
- вложенный `nested` — **та же ссылка**.

Поэтому:

```js
b.nested.n = 99;
// a.nested.n тоже 99
```

Это и есть **shallow copy**: копируется верхний уровень, вложенные объекты делятся.

Deep copy (глубокая) копировала бы вложенное тоже — это отдельная, более дорогая история. Сейчас достаточно понимать shallow.

В Dart идея та же: новый список/мапа наверху ≠ новые объекты глубоко внутри, если ты их явно не копировал.

```dart
final a = [
  [1, 2],
  [3, 4],
];
final b = [...a]; // новый внешний List
b[0].add(99);    // внутренний список общий
// a[0] тоже изменился
```

---

## 7. Как это стыкуется с `final`

(Мост к уроку 2.1)

```dart
final numbers = [1, 2, 3];
numbers.add(4);      // ок: мутация объекта
// numbers = [9, 9]; // нельзя: переприсваивание слота
```

`final` замораживает **слот**, не обязательно содержимое объекта.

---

## 8. Типичные ошибки

1. Думать, что `b = a` для объекта всегда делает независимую копию.
2. Путать `b.add(...)` и `b = [...]`.
3. Сделать shallow copy и удивляться, что вложенные данные общие.
4. Сказать «final нельзя изменить» без уточнения: нельзя переприсвоить имя; объект может быть mutable.
