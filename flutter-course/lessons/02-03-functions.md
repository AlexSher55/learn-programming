# 2.3 — Функции в Dart

Ты ещё не писал на Dart — это нормально. Ниже теория **с нуля**: сначала зачем, потом каждая деталь, потом сравнение с JS, потом контроль только по этому тексту.

---

## 1. Зачем нужны функции

Пока без функций код — длинная лента сверху вниз. Функция — **именованный кусок работы**, который можно вызывать много раз.

Аналогия: рецепт «сделать бутерброд».
- ингредиенты на входе = **параметры**;
- шаги внутри = **тело функции**;
- готовый бутерброд на выходе = **возвращаемое значение** (если оно есть).

Зачем это:
1. не копировать один и тот же код;
2. дать работе понятное имя (`add`, `greet`, `loadUser`);
3. проверять типы входа и выхода ещё до запуска.

---

## 2. Определение и вызов — две разные вещи

**Определение** — мы описываем правило:

```dart
int add(int a, int b) {
  return a + b;
}
```

**Вызов** — мы это правило запускаем:

```dart
add(2, 3); // здесь программа реально выполняет тело add
```

Пока функцию только определили, она **сама не выполняется**. Выполняется в момент вызова.

Связь с уже изученным: при вызове на call stack появляется новый **stack frame** функции. После `return` (или конца `void`-функции) кадр снимается.

---

## 3. Анатомия обычной функции

Разберём по частям:

```dart
int add(int a, int b) {
  return a + b;
}
```

| Часть | Что это | Зачем |
|---|---|---|
| `int` слева | **тип возврата** | какой тип значения функция обещает отдать наружу |
| `add` | **имя** | как вызывать |
| `(int a, int b)` | **параметры** | слоты на входе; у каждого своя бирка типа |
| `{ ... }` | **тело** | что делать |
| `return a + b;` | **возврат** | отдать результат и закончить функцию |

Важно различать слова:

- **параметр** — слот в определении: `a`, `b`;
- **аргумент** — конкретное значение при вызове: `2`, `3` в `add(2, 3)`.

При вызове `add(2, 3)`:
1. создаётся кадр `add`;
2. в слот `a` кладётся `2`, в слот `b` — `3`;
3. считается `a + b`;
4. `return` отдаёт `5` туда, откуда вызвали;
5. кадр снимается.

```dart
var result = add(2, 3); // в result попадёт 5, тип int
```

## 4. `void` — «наружу ничего полезного не отдаём»

Иногда функция только делает действие (печатает, сохраняет), а значения наружу не нужна.

```dart
void sayHi(String name) {
  print('Hi, $name');
}

sayHi('Alex');
```

`void` значит: вызывающий код **не должен** ждать полезного результата.

```dart
// var x = sayHi('Alex'); // так делать нельзя / бессмысленно для void
```

Внутри `void`-функции можно написать просто `return;` (выйти раньше), но нельзя `return 10;`.

Если тип возврата не `void` (например `int`), то функция **обязана** вернуть значение этого типа на всех путях выполнения.

---

## 5. Короткая форма `=>`

Если тело — **одно выражение**, Dart позволяет короче:

```dart
int add(int a, int b) {
  return a + b;
}

// то же самое:
int add(int a, int b) => a + b;
```

`=>` читай как: «вернуть вот это выражение».

Подходит только для одного выражения. Несколько строк, циклы, несколько операций — обычные `{ }`.

Сравнение с JS: похоже на `const add = (a, b) => a + b;`, но в Dart тип возврата и типов параметров обычно явный (или выводится аккуратнее, чем в JS).

---

## 6. Позиционные параметры (самые обычные)

Параметры идут **по порядку**. Первый аргумент → первый параметр, второй → второй.

```dart
void greet(String name, int age) {
  print('$name is $age');
}

greet('Alex', 25); // name='Alex', age=25
```

Порядок важен:

```dart
// greet(25, 'Alex'); // ошибка: 25 не String, 'Alex' не int
```

Число аргументов тоже важно: оба параметра обязательны (пока мы не сделали их optional).

```dart
// greet('Alex'); // ошибка: не хватает age
```

С JS: как обычные аргументы `function greet(name, age)`, но в Dart типы проверяет компилятор.

---

## 7. Именованные параметры `{ }`

Во Flutter их очень много (`Text(style: ...)`, `padding: ...`). Поэтому тема критичная.

Именованные параметры пишут в **фигурных скобках**. При вызове передают **по имени**:

```dart
void greet({String? name, int? age}) {
  print('$name, $age');
}

greet(name: 'Alex', age: 25);
greet(age: 25, name: 'Alex'); // порядок имён не важен
```

Почему это удобно:
- читаемость: видно, что означает каждый аргумент;
- можно передавать не все (если параметр необязательный);
- порядок вызова гибкий.

### Важный момент null safety

По умолчанию именованный параметр — **необязательный**.

Если написать так:

```dart
void greet({String name, int age}) { ... }
```

компилятор будет недоволен: необязательный параметр может отсутствовать, а `String` без `?` запрещает `null`. Нужен один из вариантов ниже.

### Три нормальных способа для named

**Способ A — `required`: обязан передать**

```dart
void greet({required String name, required int age}) {
  print('$name, $age');
}

greet(name: 'Alex', age: 25); // ок
// greet(age: 25); // ошибка компиляции: нет name
```

**Способ B — значение по умолчанию**

```dart
void greet({String name = 'Guest', int age = 0}) {
  print('$name, $age');
}

greet(); // name='Guest', age=0
greet(name: 'Alex'); // age=0
```

**Способ C — nullable (`?`), можно не передавать**

```dart
void greet({String? name, int? age}) {
  print('$name, $age'); // могут быть null
}
```

Запомни:
- `required` = «без этого аргумента вызов незаконен»;
- `= ...` = «если не передали — возьми default»;
- `Type?` = «можно не передать, тогда будет `null`».

## 8. Необязательные позиционные `[ ]`

Реже named, но встречаются.

```dart
void greet(String name, [int age = 0]) {
  print('$name, $age');
}

greet('Alex');     // age подставится 0
greet('Alex', 25); // age = 25
```

Отличия от named:

| | `[age]` | `{age}` |
|---|---|---|
| как передавать | по позиции, без имени | по имени: `age: 25` |
| порядок | важен | не важен |
| пример вызова | `greet('Alex', 25)` | `greet(name: 'Alex', age: 25)` |

Нельзя «перепрыгнуть» позиционный слот: если есть два optional positional, чтобы передать второй, первый тоже надо учесть по порядку.

---

## 9. Сводная таблица

| Вид | Запись | Вызов | Порядок | Можно не передать? |
|---|---|---|---|---|
| обязательный позиционный | `(String name)` | `f('Alex')` | да | нет |
| необязательный позиционный | `[int age = 0]` | `f('Alex')` или `f('Alex', 25)` | да | да |
| именованный необязательный | `{int age = 0}` | `f(age: 25)` | нет | да |
| именованный обязательный | `{required String name}` | `f(name: 'Alex')` | нет | нет |

---

## 10. Типичные ошибки новичка

1. Перепутать **параметр** и **аргумент**.
2. Вызвать named как позиционный: `greet('Alex')` при `{required String name}` — так нельзя, нужно `greet(name: 'Alex')`.
3. Забыть `required` / default / `?` у named и получить ошибку null safety.
4. Думать, что `=>` и `{ return ... }` — разная логика. Логика одна, запись разная.
5. Переносить из JS идею «аргументов сколько угодно и любых типов» — в Dart компилятор проверяет типы и обязательность.
