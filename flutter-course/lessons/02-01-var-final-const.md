# 2.1 — Dart: `var`, `final`, `const`

Статус: тема закрыта на 100%. Ниже полный конспект «с нуля» + архив контроля №4.

Перед этим уроком нужны: слот / ссылка / объект / mutation из `01-03`.

---

## 1. Переменная = слот с биркой

В Dart у имени всегда есть тип (бирка), даже если ты написал `var`.

Слот может хранить:
- значение (учебно для `int` и подобных);
- или ссылку на объект в heap (список, объект класса, и т.д.).

Две разные операции (не путать!):

1. **переприсвоить имя** — `age = 30`, `numbers = [9, 9]`;
2. **мутировать объект** — `numbers.add(4)`.

---

## 2. `var` — выведи тип и разреши переприсваивание

```dart
var age = 25; // Dart вывел: int
age = 30;     // ок: int → int
// age = 'Alex'; // ошибка: String ≠ int
```

Что важно:
- `var` **не** значит «любой тип как в JS»;
- тип фиксируется по начальному значению;
- дальше можно менять только значение **этого** типа.

Это почти то же, что:

```dart
int age = 25;
```

Сравнение с JS:

```js
let age = 25;
age = 'Alex'; // в JS ок
```

В Dart у `var` после вывода `int` так нельзя.

---

## 3. `final` — слот занят один раз

```dart
final age = 25;
// age = 30; // ошибка: переприсваивать нельзя
```

`final` запрещает **повторное присваивание имени**.

Но если в слоте ссылка на **mutable**-объект, объект можно менять:

```dart
final numbers = [1, 2, 3];
numbers.add(4);       // ок: тот же List, другое содержимое
// numbers = [10, 20]; // ошибка: другая ссылка в final-слоте
```

Картина:

```text
слот numbers (final) ──ссылка──► List [1, 2, 3]
                                      ▲
                                      └── add(4) меняет объект, не слот
```

С JS: `const arr = [1]; arr.push(2);` работает, `arr = []` — нет.  
JS-`const` ближе к Dart-`final`, **не** к Dart-`const`.

### Важная тонкость про `int`

```dart
final age = 25;
```

Тут нечего мутировать «внутри» числа. В учебной модели число в слоте; в Dart `int` — объект, но неизменяемый.  
Фраза «final можно менять по ссылке» верна **только для mutable-объектов** (List и т.п.), не для `int`.

---

## 4. `const` — известно компилятору и заморожено

`const` — не просто «нельзя переприсвоить».

Это **константа времени компиляции**:
- значение должно быть известно **до запуска**;
- объект заморожен (immutable).

```dart
const numbers = [1, 2, 3];
// numbers.add(4); // недопустимо
```

Поэтому:

```dart
final now = DateTime.now();  // ок: значение появится в runtime
// const now = DateTime.now(); // нельзя: now() зависит от момента запуска
```

`DateTime.now()` нельзя «запечь» заранее — часы в момент компиляции ≠ часы в момент запуска у пользователя.

---

## 5. Три оси сравнения `final` vs `const`

Не склеивай в одно «потому что».

| Ось | `final` | `const` |
|---|---|---|
| переприсвоить имя | нельзя | нельзя |
| когда известно значение | runtime или compile-time | только compile-time |
| мутация объекта | можно, если объект mutable | нельзя, объект заморожен |

`const` ⊂ более строгий случай: всё, что `const`, ещё и нельзя переприсвоить, плюс compile-time + freeze.

---

## 6. Бонус (на будущее, без отдельного зачёта)

Два одинаковых `const`-литерала компилятор может сделать **одним** объектом (каноникализация):

```dart
identical(const [1, 2], const [1, 2]); // часто true
```

Это не «копия списка», а возможный один и тот же замороженный объект. Вернёмся в коллекциях.

---

## 7. Типичные ошибки

1. Считать `var` = JS `let` без типов.
2. Говорить «final нельзя изменить» без разделения слот/объект.
3. Применять «мутацию по ссылке» к `int`.
4. Путать JS-`const` с Dart-`const`.
5. Склеивать оси `final`/`const` в одну фразу.

---

## 8. Чеклист

- `var` фиксирует тип и разрешает переприсваивание внутри типа;
- `final` замораживает слот;
- mutable через `final`-ссылку можно менять;
- `const` = compile-time + immutable;
- `DateTime.now()` только в `final`/`var`, не в `const`.
